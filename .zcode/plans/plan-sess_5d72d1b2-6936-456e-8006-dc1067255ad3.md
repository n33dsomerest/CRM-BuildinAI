## Phase 1 — Prisma schema + seed
Models (FK + index ครบ):
- **User** (email unique, passwordHash, name, role ADMIN|SALES)
- **Account** (name, industry, website, phone, ownerId) — บริษัท
- **Contact** (name, email, phone, position, accountId, status PROSPECT|CUSTOMER, ownerId)
- **Lead** (name, email, phone, company, source WEB|REFERRAL|EVENT|COLD_CALL|OTHER, status NEW|WORKING|QUALIFIED|UNQUALIFIED, ownerId)
- **Stage** (name, order, probability, isWon, isLost) — seed 6 คอลัมน์: New Lead 10% → Contact Made 25% → Proposal 50% → Negotiation 75% → Won 100% → Lost 0%
- **Deal** (title, value, stageId, contactId, accountId, ownerId, expectedCloseDate)
- **Activity** (type NOTE|CALL|MEETING|EMAIL, subject, body, contactId, dealId?, userId, occurredAt)
- **Task** (title, dueDate, status OPEN|DONE, contactId?, dealId?, assigneeId)
- **AuditLog** (entity, entityId, action CREATE|UPDATE|DELETE, userId, changes Json)
- Seed: users 2 (admin+sales), stages 6, accounts 8, contacts 25, leads 10, deals ~30 กระจายทุก stage, activities, tasks มี overdue ปนอยู่

## Phase 2 — Backend (Zod + Server Actions)
- zod schemas ทุก entity + login • Auth.js credentials + session แนบ role • middleware บังคับ login ทุก route ยกเว้น `/login`
- data-access layer มี **scoping ทุก query**: SALES เห็นเฉพาะ `ownerId = ตัวเอง`, ADMIN เห็นหมด
- Server Actions: contacts/accounts/deals CRUD, deals moveStage, **leads convertLead** (transaction เดียวสร้าง Account+Contact+Deal), tasks toggle, activities add/list, contacts **import/export CSV**, dashboard aggregates (Pipeline Value, Weighted Forecast, Total Contacts, Won Deals, Conversion Rate, funnel ต่อ stage)
- audit helper ผูกเข้าทุก mutation อัตโนมัติ
- ทุกหน้าที่ query DB เป็น dynamic → `next build` ผ่านแม้ยังไม่มี DATABASE_URL จริง
